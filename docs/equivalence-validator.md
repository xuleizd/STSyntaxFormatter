# 等价性校验器（FormattingValidator）行为契约

版本：1.8.8 起。代码：`src/STFormatterCore/Validation/FormattingValidator.cs`。
对标 CSharpier 的 `IFormattingValidator` / `SyntaxNodeComparer`，但适配 ST 与本项目的解析器。

## 动机

本项目的历史 bug（1.8.6 REPEAT 吞语句、1.8.7 STRUCT RETAIN 被删、1.8.4 的三处丢注释）
全部是"格式化输出悄悄改了代码"这一类，且全部靠用户报告才发现。校验器把这类破坏变成
**当场拦截**：格式化结果写回磁盘/编辑器之前，机器验证它没有改坏任何东西。

## 契约

**格式化只允许改变三件事**：
1. 空白与换行（缩进、空行策略、行尾空白）
2. 关键词大小写（一律大写）
3. 类型名大小写（`TypeCase` 选项）

**除这三件事外，格式化输出必须与源等价**。校验器用三道比对强制这一点：

### 第 1 道：有效 token 序列
- 源文本与输出各自重新 Lexer→Parser，收集 CST 里的 token（按源序），逐位比对
  Kind + 归一化 Text。
- **归一化**：关键词/标识符大小写不敏感（因为第 2、3 件合法改变无法与"变量名被改"区分，
  统一放行大小写）；字符串/类型化字面量/直接地址/数字字面量**逐字符敏感**（字符串绝不能被碰）。
- **白名单**（不参与比对的 token）：
  - `UnknownNode` 子树内的全部 token——解析器把无法解析的残渣（语句间的孤立 `;` 等）放在
    这里，规范化掉它们是既定的格式化行为；
  - STRUCT/UNION body token 里非头部token——成员在子节点里，其余 token 同为残渣。
- 抓住：token 被删（RETAIN 消失）、被发明（凭空补 `;`）、被改（字符串内容）、被重排
  （END_REPLEAT 后移导致顺序变化）。

### 第 2 道：CST 形状（节点类型 + 嵌套深度）
- 递归收集"节点类型名 + 深度"序列比对（跳过 UnknownNode）。
- **深度是形状的一部分**：语句从循环外挪进循环内时，扁平 token 序列可能不变，但深度变了。
- 抓住：构造被重组（语句被吞进 UNTIL 条件、成员挂错块）。

### 第 3 道：注释多重集
- 对源与输出的**全量 token 列表**（不是语法树！）收集 trivia 里的所有注释，文本去除全部
  空白后做多重度集合比对。
- 必须用全量 token 列表的原因：畸形输入下解析器可能丢弃从未进入任何节点的 token，
  挂在它们身上的注释对树遍历不可见——而那正是注释最危险的时刻（`_Safety` 样例）。
- 抓住：注释丢失、注释被复制、注释内容被改。`//x` → `// x` 的间距规范不算内容变化。

## 调用方义务（写回策略）

校验失败的文件**必须保持原样**：
- **CLI**（`TcPouFile.FormatCode`）：默认校验（`--skip-validation` 可关）；失败抛异常 →
  上层 catch 跳过 `Save()` → 磁盘文件不动，计入失败、退出码 1。
- **VSIX**：写编辑器 buffer 前校验，失败跳过格式化并保留原文（1.8.9 方案 D 落地）。

一个被拒绝的文件永远好过一个被改坏的文件。

## 已知边界

- 解析器丢弃的畸形 token 本身（非其注释）不在第 1 道的可见范围内——与"垃圾规范化"的
  既定行为一致。
- 已知损坏样例 `testdata/_Auto.TcPOU`、`testdata/_Safety.TcPOU` 会被校验器拒绝
  （`TestdataCorpusSweep` 的 `KnownCorruptSamples` 名单）；拒绝是这些文件的正确结局。
